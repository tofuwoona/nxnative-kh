## Depth-clear fix and verification

The normal depth-test path initially showed the tutorial text over black. An opt-in depth-comparison bypass restored the scene but produced incorrect occlusion, implicating depth handling without proving the cause. `DM_VK_CLEARTRACE=1` then showed that the game issues a full color clear and depth-to-1 clear through `vkCmdClearAttachments` each frame. In the new Vulkan clear implementation, the temporary Metal clear encoder inherited `MTLStoreActionUnknown` and ended without setting store actions, while the resumed pass loaded those attachments. The fix sets store actions on the temporary encoder before it ends, preserving every active color attachment (including multisample resolve handling via `keep`) and active depth/stencil attachments for subsequent loads.

The Program 1 host build and host test suite passed after the change (`run/clearstore_build.log`, `run/clearstore_tests.log`). A clean-save Mac run with normal depth testing and Metal validation enabled reached the 3D tutorial: `program1_run/clearfix_12000.png` and `clearfix_15000.png` show Sora, the platform and pedestal, with Sora occluding the pedestal; the depth-override diagnostic had drawn the pedestal through him. This is strong evidence the clear-store change fixes the observed missing-scene/depth issue; image comparisons were from separate runs and later gameplay, texture issues, and exhaustive Vulkan clear cases are not verified. No dedicated automated Vulkan clear regression test was added; existing host tests do not exercise this Metal path. Diagnostic depth/cull bypasses are opt-in and were not used in the clear-fix run.

### a552 shader deep dive and synthetic GPU probe
